# 手机与浏览器兼容

## 网络与初始化分开诊断

地图引擎、名单、学校点、省级与世界轮廓内嵌在 HTML。在线街道与字体使用 `tiles.openfreemap.org`，在基础 3D 地图成功加载后才尝试请求。国外服务访问失败应静默回退，不能据一张“地图加载超时”截图认定是网络封锁。

绕过 HTTP 代理的本机直连探测曾出现索引/字体成功和连接超时混合结果；这仅证明当时该网络的表现，不能外推全国、所有运营商或某台手机。

## 渲染策略

- 正常设备先使用 MapLibre。手机或粗指针设备将像素倍率上限限制到 1.5、画布上限 2560×2560、关闭抗锯齿，初始倾斜不超过 25°；省份挤出和街道建筑立体效果也做减负。桌面保留原有立体体验。
- 无 Worker、WebGL/引擎构造失败时立即使用 Leaflet 1.9.4；初始 3D 加载超过 8 秒时自动切换。图形上下文丢失时也切换，不让用户停留在错误遮罩上。
- 二维渲染器与 3D 引擎独立，使用同一份业务数据和内嵌 GeoJSON，保持省份/国家人数、学校点、母校连线、搜索、名册、详情和 JSON 导出。用 Leaflet 原生触摸交互支持双指缩放和单指拖动。
- 二维不支持倾斜/旋转或当前的在线矢量街道；相应控件禁用，不弹联网告警。保留用户手动关闭连线/标签的选择，运行中切换保留学校选择和详情。
- 加载成功必须隐藏旧错误层；已被移除的旧 3D 实例迟到的加载事件不得重置当前二维地图。

不要把“设置 3D 地图的 pitch 为 0”当作独立二维兼容方案：那仍依赖同一个 WebGL 和 Worker。不要仅按 UA 中是否含 Xiaomi/MIUI 判断设备能力。

## 小米相关公开证据

核验日期：2026-11-08。

MapLibre 官方问题 [#4487：3D Terrain significantly decrease performance of the map](https://github.com/maplibre/maplibre-gl-js/issues/4487)，及 [2024-08-12 的设备补充](https://github.com/maplibre/maplibre-gl-js/issues/4487#issuecomment-2284486660)，有报告者说明使用 Xiaomi Note 12 Pro 5G，Android WebView/Chrome 的 3D 地形在高缩放下明显变慢；维护者确认地形实现存在性能限制。

**该案例不是本项目超时的复现**：本项目没有 DEM 地形，此处也没有用户手机型号、内核版本和打开方式。它只能作为“Android 图形负担和浏览器差异值得实测”的参考，不作为给某个小米机型打补丁的依据。未核实到与当前截图完全相同的小米原生浏览器故障。未能读取核验的 Mi Browser 社区页面不作为事实引用。

实现按实际能力退让，不复制不适用的地形修复、品牌黑名单、浏览器升级建议或来历不明的图形参数。

## 验证

`tests/compatibility.cjs` 使用完全虚构的演示，覆盖引擎缺失、WebGL 不可用、Worker 缺失/受限/不响应、图形上下文丢失、旧实例迟到事件、高 DPR、二维真实触摸事件、横竖屏控件、名单与导出。测试通过只能称浏览器故障模拟验证，不能称小米实机验证。

后续获得设备信息时，记录机型、系统/浏览器版本、实际打开协议（本地文件、微信预览或 HTTPS）及失败阶段；在该设备复测后再给出设备专属结论。

Leaflet 参考：[1.9.4 API](https://leafletjs.com/reference-1.9.4.html)；固定版本代码与 BSD-2-Clause 许可内嵌在技能资源和生成 HTML 中。MapLibre 固定版本仍为 5.6.2，不因一次设备反馈无依据升级整个引擎。
