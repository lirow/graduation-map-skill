# 记录合并、冲突与交付

## 分析记录

先形成工作记录，再映射到 [data-schema.md](data-schema.md)。工作记录至少能回答：

| 槽位 | 用途 |
|---|---|
| 稳定人员 ID | 后续更正的锚点，与排序无关；可用内部 ID，不必收集真实学号 |
| 当前姓名与去向 | 当前显示值、所属届别/班级、去向阶段 |
| 学校和位置 | 学校/校区 ID、国家/省市、地址和 WGS84 坐标 |
| 待补字段 | 哪些值未知、有冲突，需要用户修改或接受留空 |

只保留当前业务记录和未知状态，不要求保存原文摘录、来源位置、旧 OCR、修改历史或证据档案。用户输入原件不因这项清理而被删除。

## 合并判断

1. 用户已明确指认某条 ID 的更正，按该人、该字段应用。旧值不继续进入当前数据或人数/去向统计。
2. 原始名单与校订表有明确对应关系时按对应标识合并。仅文件更新、sheet 叫“最新”、OCR 更自信，都不能自动胜过明确确认。
3. 没有稳定标识时，用班级/年份、姓名、学校等上下文提出候选匹配；不单凭同名合并。同一人有多所候选学校也不拆成多个人。
4. 无法裁定的去向留空，在核对表中说明需要用户修改的字段；不要为完成地图任选一校。已确认的姓名不因学校仍有疑点而退回待核。
5. 学校别名先确认机构身份，再决定显示名；同校不同校区分开。确认学校现址不能确认历史就读校区。

默认一人按本次指定届别和阶段统计一次。转学、复读后再次录取、联合培养、多个 offer 先明确展示口径；不将多个阶段同时计入一个人的最终去向。就业、待录取、复读、暂不升学是有效毕业状态，应保留在名单或单独状态汇总，不能伪装成学校。现有模板以升学学校为中心，超出其状态展示能力时由 agent 调整展示或另附说明，不能承诺模板已有就业专题功能。

## 人数与完整性对账

分别核对原始明细条数、重复证据、可区分人员数、待核人员、学校/校区数、地区归属和已定位人数。表头、小计、合计、透视表和截图重复不是新人员。多人同校少的是点位，不是人数。

班级总人数是独立声明。只有用户确认范围完整，且与已识别人员及待核项一致，才设 `meta.rosterComplete: true`。没有名单的人不通过虚构姓名凑齐；“还缺 1 人”不等于存在一条已知身份的人员记录。总人数、缺失人数、追加人员互相冲突时保持不完整，提出具体差异。

只知道地区的学生保留在该地区统计；国家/省份未知的保留在待补分组。无坐标不减少总人数，模糊姓名的一条独立记录也不应被漏掉。用户确认整份当前数据并接受未知项后可制作草稿，清楚标明已收录数量，未定去向不生成假点。

## 虚构分析示例

输入：TXT“甲大学：陈一、林二”；Excel 原始表有 `001 陈一 甲大学`、`002 林二 甲大学`、`003 王三 乙大学`，另有汇总表与修订表 `002 林二 丙大学`；对话“002 改丙大学，另一位林二去丁大学；全班 4 人，还缺 1 人”。

处理：TXT 与原始表作为可能重叠证据，核对上下文后合并；汇总不新增学生；002 只计入丙大学。另一位林二是不同人，分配内部临时 ID 并保留丁大学去向，不捏造真实学号。已有四个人员声明却又称还缺一人，完整性存在冲突，不能宣称名单齐全。实际 sheet 行号未提供时不编造单元格地址。此例仅说明判断方式，不代表完成过真实 Excel/TXT 读取测试。

## 完整核对与确认

分析完先交付以下完整数据，不能只列疑点或抽样几行：

1. 全部学生：ID、姓名、学校/校区、国家/省市、毕业去向状态及待补项。
2. 全部学校/校区：ID、名称、地区、地址、WGS84 经度/纬度及校区确认状态；同学表通过 ID 对应。
3. 班级/届别、完整性声明、母校信息、地图设置和人数汇总。

短名单直接给完整表，长名单提供可阅读和编辑的完整表文件，并在对话给出人数和待补字段。明确请用户检查每条数据；有问题可编辑表格，或回复“ID + 字段 + 正确值”。只更正明确指定的字段。

此时停止，不生成 HTML 或地图草稿。用户对展示的当前版本明确说“数据确认，可以生成”后才能开始。只说“请做地图”、声明名单完整、没有发现疑点、未回复，均不算当前数据已确认。用户修改后重新展示完整更新版，再等确认；单独一条更正不代表确认整份数据。可明确接受未知字段继续留空，不必为填满字段编造资料。

确认后交付可直接打开的 HTML，按需附当前 JSON 和简短的数量/未知项/实际验证说明。成品和导出不含原图、来源链接或举证档案。后续数据发生变化时重新经过完整核对和确认，继续沿用稳定 ID。

## 常见错误

| 错误 | 正确处理 |
|---|---|
| Excel 明细 + 汇总再次相加 | 汇总只对账 |
| 同名自动合并、排序后按行更正 | 按稳定身份关联，歧义单独列出 |
| 用户确认姓名就确认学校和校区 | 分字段保留确认状态 |
| 多图重叠区域重复计数 | 对照原位置和上下文 |
| 缺数据就补姓名、填省会坐标 | 保留未知，用户确认后才制作 |
| 把方法支持写成已完成真实导入 | 分清分析规范、虚构演练和真实验证 |
| 没有疑点或收到一条更正就直接生成 | 展示完整当前版，等待用户明确确认 |

> 维护约定：完整数据核对取代来源举证；不要恢复先生成草稿后让用户追溯原图的流程。
