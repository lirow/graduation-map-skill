# 记录合并、冲突与交付

## 分析记录

先形成工作记录，再映射到 [data-schema.md](data-schema.md)。工作记录至少能回答：

| 槽位 | 用途 |
|---|---|
| 稳定人员 ID | 后续更正的锚点，与排序无关；可用内部 ID，不必收集真实学号 |
| 原文与来源 | `sourceId`、文件/消息、页/行/sheet/区域等真实可取得的位置 |
| 当前姓名与去向 | 原文、规范化显示值、所属届别/班级、去向阶段 |
| 字段证据 | 姓名、学校、校区、地区/坐标各自的依据与待核状态 |
| 变更与冲突 | 被哪个明确更正替代、仍有哪些候选、需要用户确认什么 |

可以在本地工作表或校对说明中维护这些信息，不要求新增运行时字段。页面导出只保留任务所需证据，避免整段聊天或私人字段被顺带公开。

## 合并判断

1. 用户已明确指认某条 ID 的更正，按该人、该字段应用。原始证据可保留；旧值不继续进入当前人数/去向统计。
2. 原始名单与校订表有明确对应关系时按对应标识合并。仅文件更新、sheet 叫“最新”、OCR 更自信，都不能自动胜过明确确认。
3. 没有稳定标识时，用班级/年份、姓名、学校、来源位置等上下文提出候选匹配；不单凭同名合并。同一人有多所候选学校也不拆成多个人。
4. 无法裁定的去向保留候选证据，当前去向可留空；不要为完成地图任选一校。已确认的姓名不因学校仍有疑点而退回待核。
5. 学校别名先确认机构身份，再决定显示名；同校不同校区分开。确认学校现址不能确认历史就读校区。

默认一人按本次指定届别和阶段统计一次。转学、复读后再次录取、联合培养、多个 offer 先明确展示口径；不将多个阶段同时计入一个人的最终去向。就业、待录取、复读、暂不升学是有效毕业状态，应保留在名单或单独状态汇总，不能伪装成学校。现有模板以升学学校为中心，超出其状态展示能力时由 agent 调整展示或另附说明，不能承诺模板已有就业专题功能。

## 人数与完整性对账

分别核对原始明细条数、重复证据、可区分人员数、待核人员、学校/校区数、地区归属和已定位人数。表头、小计、合计、透视表和截图重复不是新人员。多人同校少的是点位，不是人数。

班级总人数是独立声明。只有用户确认范围完整，且与已识别人员及待核项一致，才设 `meta.rosterComplete: true`。没有名单的人不通过虚构姓名凑齐；“还缺 1 人”不等于存在一条已知身份的人员记录。总人数、缺失人数、追加人员互相冲突时保持不完整，提出具体差异。

只知道地区的学生保留在该地区统计；国家/省份未知的保留在待补分组。无坐标不减少总人数，模糊姓名的一条独立记录也不应被漏掉。需要制作草稿时清楚标明已收录数量，未定去向不生成假点。

## 虚构分析示例

输入：TXT“甲大学：陈一、林二”；Excel 原始表有 `001 陈一 甲大学`、`002 林二 甲大学`、`003 王三 乙大学`，另有汇总表与修订表 `002 林二 丙大学`；对话“002 改丙大学，另一位林二去丁大学；全班 4 人，还缺 1 人”。

处理：TXT 与原始表作为可能重叠证据，核对上下文后合并；汇总不新增学生；002 只计入丙大学。另一位林二是不同人，分配内部临时 ID 并保留丁大学去向，不捏造真实学号。已有四个人员声明却又称还缺一人，完整性存在冲突，不能宣称名单齐全。实际 sheet 行号未提供时不编造单元格地址。此例仅说明判断方式，不代表完成过真实 Excel/TXT 读取测试。

## 交付给用户

正常制作地图时，交付可直接打开的 HTML，附简短的校对/数据说明；按需要提供可编辑 JSON。说明包括来源覆盖范围、已收录数量、未解决项和实际做过的验证。不要只交一个脚本让用户自行完成读取、校对和制作。

疑点清单按稳定 ID 给出“原文/当前值、来源、疑点、需要确认的字段”。可以先完成有用草稿；影响具体人员身份或人数的歧义不能静默裁定。后续对话更正继续沿用原 ID，重新计算统计并核对地图、名单、详情和导出。

## 常见错误

| 错误 | 正确处理 |
|---|---|
| Excel 明细 + 汇总再次相加 | 汇总只对账 |
| 同名自动合并、排序后按行更正 | 按稳定身份关联，歧义单独列出 |
| 用户确认姓名就确认学校和校区 | 分字段保留证据 |
| 多图重叠区域重复计数 | 对照原位置和上下文 |
| 缺数据就补姓名、填省会坐标 | 保留未知，交付可用草稿 |
| 把方法支持写成已完成真实导入 | 分清分析规范、虚构演练和真实验证 |
